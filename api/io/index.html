    sylva.io¶

    sylva.io ¶

    Reading and writing point clouds.

    read and write dispatch on file extension:

    Format read write
    .las / .laz yes yes
    .ply (ascii / binary, incl. raycloudtools ray clouds) yes yes
    .xyz .txt .csv .pts yes yes
    .rxp (RIEGL, needs RiVLib) yes no

    Pulse data has its own format, see sylva.Shots.save.

    read ¶

    read(path: str | Path) -> PointCloud

    Read a point cloud, choosing the reader from the file extension.

    Parameters:

    Name Type Description Default
    path str | Path

    .las, .laz, .ply, .xyz, .txt, .csv, .asc, .pts or .rxp. The extension is matched case-insensitively.

    		 required

    Returns:

    Type Description
    PointCloud

    Coordinates in the file's frame (.rxp: scanner frame, see read_rxp). Attributes depend on the format:

    • LAS/LAZ: intensity, return_number, number_of_returns, classification, scan_angle, user_data, point_source_id, plus gps_time and red/green/blue when the point format has them, and every extra-bytes dimension under its own name and type. crs is the header's OGC WKT, or "EPSG:n" ("EPSG:h+v" with a vertical CRS) from its GeoTIFF keys; None if the header declares neither.
    • PLY: every vertex property except x, y, z, with its type. raycloudtools ray clouds give nx, ny, nz (point to sensor) and alpha; see sylva.Shots.from_ray_cloud.
    • Text: see read_ascii.
    • RXP: see read_rxp (default options).

    Raises:

    Type Description
    OSError

    If the file cannot be opened or is malformed.
    ValueError

    For an unsupported extension or invalid option.

    write ¶

    write(cloud: PointCloud, path: str | Path, point_format: int = 6, scale: float | None = None, binary: bool = True) -> None

    Write a point cloud, choosing the writer from the file extension.

    Parameters:

    Name Type Description Default
    cloud PointCloud

    Points to write, with all their attributes.

    		 required
    path str | Path

    .las, .laz, .ply, .xyz, .txt, .asc, .pts (space separated) or .csv (comma separated). Overwritten if it exists.

    		 required
    point_format int

    LAS point data record format (LAS/LAZ only). 6 (LAS 1.4, with GPS time) is the default; use 7 or 8 to keep RGB.

    		 6
    scale float | None

    LAS coordinate quantisation in the units of the coordinates (LAS/LAZ only); the offset is the floor of the minimum coordinate. By default 0.001 (millimetres), or 1e-7 degrees (about 1 cm) when the cloud's crs is geographic (longitude and latitude).

    		 None
    binary bool

    Binary little-endian PLY if True, ASCII otherwise (PLY only).

    		 True
    Notes

    LAS/LAZ: attributes that are not standard dimensions of point_format are written as typed extra bytes, so height, tree_id and the like survive a round trip. The cloud's crs is stored as an OGC WKT VLR (an EPSG code as the registry's WKT); a CRS given as a PROJ string has no WKT form and is left out with a warning. Text files get a header line naming the columns and coordinates to 0.1 mm; integer attributes are written as integers. PLY and text files have no place for a CRS.

    Raises:

    Type Description
    OSError

    If the file cannot be opened or is malformed.
    ValueError

    For an unsupported extension or invalid option.

    read_ascii ¶

    read_ascii(path: str | Path, columns: list[str] | None = None) -> PointCloud

    Read a delimited text point cloud.

    The delimiter (comma, semicolon, tab or whitespace) is detected from the first data line. Lines starting with # are skipped, a leading line holding a single integer (PTS point count) is skipped, and a non-numeric first line is taken as a header.

    Parameters:

    Name Type Description Default
    path str | Path

    Text file whose first three columns are x, y, z.

    		 required
    columns list[str] | None

    Names for the columns. Either all columns (the first three are then ignored) or only the ones after x, y, z. Overrides a header line. Without names or header, extra columns are called col3, col4, ...

    		 None

    Returns:

    Type Description
    PointCloud

    Extra columns as float64 attributes.

    Raises:

    Type Description
    OSError

    On a non-numeric value, a row with a different column count, fewer than three columns, or a file that cannot be opened.

    read_rxp ¶

    read_rxp(path: str | Path, **options) -> PointCloud

    Read a RIEGL .rxp scan as points.

    Needs RiVLib's libscanifc, which RIEGL does not allow to be redistributed; see find_rivlib for where it is looked for.

    Parameters:

    Name Type Description Default
    path str | Path

    The .rxp file of one scan position.

    		 required
    **options

    Keyword options:

    • library (path): libscanifc or a directory containing it.
    • drop_pseudo_echoes (True): skip echoes RIEGL flags as pseudo.
    • min_range (0.5): drop echoes closer than this (m); removes the tripod and operator.
    • max_range (inf): drop echoes farther than this (m).
    • stride (1): keep every n-th echo. Splits multi-echo pulses, so do not use it for pulse data.
    • shot_stride (1): keep every n-th pulse with all its echoes; the right way to thin data for gap fraction and ray tracing.
    • max_points (None): stop after this many points.
    • echoes ("all"): "all", "first", "last" or "single".
    		 {}

    Returns:

    Type Description
    PointCloud

    Points in the scanner's own coordinate system (SOCS), scanner at the origin. Apply the SOP (read_matrix_file or sylva.riscan.RiscanProject) to put them in project coordinates. Attributes: amplitude and reflectance (dB), deviation (pulse-shape deviation, higher = more distorted), echo_type (0 single, 1 first, 2 interior, 3 last) and gps_time (s).

    Raises:

    Type Description
    ValueError

    If RiVLib cannot be found or reports an error reading the file.

    read_rxp_shots ¶

    read_rxp_shots(path: str | Path, **options) -> Shots

    Read a RIEGL .rxp scan as pulses.

    Echoes sharing a timestamp are grouped into one pulse. RIEGL records only pulses that returned something, so misses must be added afterwards with sylva.Shots.fill_missing for gap fraction and ray tracing.

    Parameters:

    Name Type Description Default
    path str | Path

    The .rxp file of one scan position.

    		 required
    **options

    As for read_rxp. Thin with shot_stride, not stride.

    		 {}

    Returns:

    Type Description
    Shots

    Pulses in the scanner frame (origin at 0, 0, 0), with the echo attributes of read_rxp. Transform with the SOP before combining scans.

    Raises:

    Type Description
    ValueError

    If RiVLib cannot be found or reports an error reading the file.

    find_rivlib ¶

    find_rivlib(hint: str | Path | None = None) -> Path

    Locate RiVLib's libscanifc shared library.

    Parameters:

    Name Type Description Default
    hint str | Path | None

    A file, or a directory to search (three levels deep) first.

    		 None

    Returns:

    Type Description
    Path

    The library found. After hint, the search order is $RIVLIB_PATH, $RIVLIB_HOME, ~/.local/lib, ~/.local, ~/lib, ~/opt, ~, /opt, /usr/local/lib, /usr/local and /usr/lib, looking in subdirectories whose name contains "rivlib".

    Raises:

    Type Description
    ValueError

    If no libscanifc is found. Set RIVLIB_PATH to the extracted RiVLib directory.
